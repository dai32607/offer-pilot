# OfferPilot · JD-简历匹配分析平台

> 基于大模型的招聘匹配分析系统：将 JD 与简历结构化后做多维加权评估，输出匹配得分、缺口项与改写建议，并提供 AI 面试官多轮模拟面试能力。

## 核心特性

- **全链路分析闭环**：覆盖「JD 解析 → 简历解析 → 匹配评估 → 改写建议 → AI 面试官」完整链路，每个阶段产出结构化中间结果，便于追踪与回放。
- **结构化输出约束**：所有解析与评估环节均要求模型输出严格 JSON，配合容错提取（剥离代码块包裹、截取首尾大括号）与 Jackson 反序列化校验；校验失败时将错误回传模型重试，避免模型自由发挥导致下游解析崩溃。
- **多维加权评分**：按硬性技能、经验年限、项目成果、教育证书、加分项与潜力五个维度分别评分，加权汇总为整体得分与等级，同步输出命中项、缺口项与风险提示。
- **证据反幻觉校验**：对模型给出的每条匹配证据执行原文子串校验，无法在 JD 或简历原文中命中的证据视为无效；对应维度标记为不确定并从总分中剔除，剩余权重重归一化，避免模型臆造结论抬高分数。
- **改写建议生成**：基于匹配报告中的命中项、缺口项、风险与维度得分，结合简历原文生成改写建议，输出原文片段、改写文本、改写理由与关联缺口，缺项可空。
- **AI 面试官模拟面试**：依据简历与 JD 生成面试问题，逐轮追问形成完整会话，每轮输出评分与总结，支持整场面试过程快照回放。
- **离线快照回放**：内置分析报告与面试会话快照，可在完全离线、无 API Key 的环境下逐轮回放完整流程，便于演示与结果追溯。

## 技术栈

| 层 | 技术 |
|---|---|
| 后端 | Java 21 · Spring Boot 3.2 · Maven |
| 前端 | Vue 3 · Vite · Element Plus |
| 大模型 | DeepSeek（OpenAI 兼容 Chat Completions 协议），按任务类型路由至不同模型 |
| 数据交换 | JSON 结构化 DTO · SSE 事件流 |

## 处理流程

```
JD 原文  ──▶ JD 解析 Agent      ──▶ 结构化职位画像
简历原文 ──▶ 简历解析 Agent    ──▶ 结构化候选人画像
                                        │
                                        ▼
                              匹配评估 Agent（多维加权评分）
                                        │
                          ┌─────────────┴─────────────┐
                          ▼                           ▼
                  证据反幻觉校验                  改写建议生成
                          │                           │
                          └─────────────┬─────────────┘
                                        ▼
                              匹配报告 + 面试官会话
```

模型路由策略：解析类轻量任务使用 `deepseek-flash`，评估、改写与面试官等推理任务使用 `deepseek-v4-pro`，通过两个命名 Bean 分别注入，便于按任务特性切换。

## 快速开始

### 环境要求

- JDK 21
- Maven 3.8+
- Node.js 18+ / npm

### 后端

```powershell
# 设置 JDK 路径（替换为本地实际安装位置）
$env:JAVA_HOME = "<你的 JDK21 安装目录>"

# 可选：配置大模型 API Key，未配置时服务仍可启动，仅 LLM 调用失败
$env:DEEPSEEK_API_KEY = "<你的 API Key>"

cd backend
mvn spring-boot:run
```

后端默认监听 `8083` 端口，主要接口：

| 接口 | 说明 |
|---|---|
| `GET /api/v1/replays` | 演示快照清单（匹配快照与面试快照） |
| `POST /api/analysis` | 创建分析任务，返回任务 JSON |
| `GET /api/analysis/events` | SSE 进度事件流 |

### 前端

```powershell
cd frontend
npm install
npm run dev
```

前端默认监听 `5173` 端口，开发服务器已将 `/api` 请求代理至后端 `8083`。

## 配置说明

后端 `application.yml` 中的 API Key 使用环境变量占位，仓库内不写入任何真实密钥：

```yaml
deepseek:
  api-key: ${DEEPSEEK_API_KEY:}
```

本地开发时通过环境变量注入，切勿将真实 Key 提交至版本库。

## 已知限制

- 匹配得分为多维度加权计算的综合评估结果，用于辅助筛选与自我优化，不代表招聘决策。
- 未配置 API Key 时，依赖大模型的环节将降级或失败，离线快照回放不受影响。
- 评测集规模有限，模型在长文本与中英混合输入下的稳定性仍在持续验证。
